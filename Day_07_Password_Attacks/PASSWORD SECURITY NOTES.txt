Name: Christian Adam Anilbhai

1. BRUTE FORCE
Systematically trying different password combinations.

2. DICTIONARY ATTACK
Using a predefined list of common passwords.

3. CREDENTIAL STUFFING
Using leaked username and password combinations
against other services.

4. DEFENSIVE MEASURES

- Rate limiting
- Account lockout
- CAPTCHA
- Multi-factor authentication
- Breach monitoring
- Login activity monitoring

5. LAB IMPLEMENTATION

- Flask local login server.
- Three failed attempts allowed.
- Temporary lockout for 60 seconds.
- Python requests-based test simulator.

6. CONCLUSION

Rate limiting helps protect login systems
against automated password guessing.
Combining rate limiting with MFA and monitoring
provides stronger account security.
